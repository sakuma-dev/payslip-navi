# 給与明細ナビ — GUI設計

2026-09-28 / Claude Opus 5.5 medium。承認済み `ARCHITECTURE.md` と `CONTRACTS.md` v1 が前提。UIは `src/domain` と `src/services` の公開exportだけを使う。

## 方針

- 最初に目に入るのは手取り（差引支給額）。次に前月との差、その次に内訳という順で情報を置く。
- 明細から計算した差（事実）と、考えられる理由（可能性）は見出しと色で分ける。可能性の側には必ず出典と確認日を付ける。
- 「算術チェック」は、総支給・控除・調整の数字が互いに合っているかの確認であり、税額の判定ではないと画面上で常に書き添える。
- 値が無いとき、「未入力」「内訳未登録」「データなし」と「0円」は、見た目でも文言でも区別する。
- 保存・置換・削除は、確認してから実行する。成功したことを確認できたときだけ画面を移る。

## 画面構成（router不要。App.tsx の状態で切り替える）

```
起動 ─ 読込中 ─┬─ 失敗: エラー文言 / 再試行 / デモで体験（実データを別方式で保存しない）
              └─ 準備完了 ─┬─ 実データ0件かつ未案内 → 初回案内（端末内だけに保存・機種変更はJSONバックアップ）
                           │                          → サンプルで体験 / 自分の明細を追加
                           └─ 4タブ: ホーム / 履歴 / 項目ガイド / 設定
上に重ねる画面（stack、Androidの戻る操作に対応）
  追加方式: 写真 / 撮影 / テキスト貼付 / 手入力
    → 確認・編集: 支払月 / 3つの合計 / 支給・控除・調整の項目 / 算術チェック / 本人確認 → 保存
    → 保存成功 → 明細詳細（確認・編集画面をこの画面で置き換える）
  明細詳細: 合計 / 内訳 / 前月・前年同月との比較 / 編集 / 削除（確認あり）
```

- **ホーム:** 最新の支払月の手取りを大きく表示し、総支給と控除、前月差と前年同月差を並べる。確認ポイント（insights）と、選んだ年の手取り推移の棒グラフを置く。
- **履歴:** 年ごとに区切った月の一覧。各行に手取りと前月差を表示する。前月が未登録の場合は「前月データなし」と表示し、直前に登録した月とは比べない。
- **項目ガイド:** `GUIDE_ENTRIES` の平易な説明と出典（確認日付き、外部ブラウザで開く）。住民税は「横浜市の案内（例）」として表示する。
- **設定:**
  - データ件数、バックアップの書き出し、復元（全置換）、全削除
  - デモの開始・終了
  - 保存についての説明（端末内だけに保存、OSのバックアップ対象外、暗号化・署名なし）

## スタイル

- 色:
  - 紙のような背景 `#F5F3EE`、白いカード、文字 `#1E292D`
  - 主色は深い青緑 `#1F5F5B`
  - 増えた（手取りが上がった）は青緑、減ったはテラコッタ `#B4533A`（赤で不安を煽らない）
  - 注意は琥珀、エラーは煉瓦色、デモは紫 `#5B4B8A`。デモ中は画面上部に常に帯を表示する
- 数字: システムフォントに `tabular-nums` を付けて桁を揃える。手取りは 36pt。金額は右揃え。差額は `+`/`−` の記号に加えて「増/減」の文言も出す（色だけに頼らない）。
- 部品: 角丸16のカード、最小の押下領域44pt、主ボタンは塗り、副ボタンは枠線、危険な操作は煉瓦色の枠線。
- 読み上げ:
  - 金額は「12万3456円」、負の値は「マイナス」と読ませる
  - グラフは全体をまとめた説明文を持ち、「数値一覧」で同じ内容を表として表示できる
- 外部の画像・フォント・アイコンは使わない。アイコンは使わず、文字と形で表す。

## 状態とエラー

| 状況 | 表示 |
| --- | --- |
| 読込中 | 読込中の表示と「端末内のデータを準備しています」 |
| repository の準備失敗 | services が返す文言、再試行、デモで体験。別の保存方式には切り替えない |
| Webプレビュー | 常時帯「プレビュー：保存されず、再読込で消えます」 |
| デモ中 | 常時帯「デモ（架空データ）」と終了ボタン。書き出し・復元・全削除は無効 |
| OCR `unavailable` | 「写真の読み取りには開発ビルドが必要です」。テキスト貼付・手入力へ案内 |
| OCR `permissionDenied` | 権限が必要な理由と「設定を開く」 |
| OCR 成功だが 0 行 | 「読み取れませんでした」と、撮り直す・手入力 |
| OCR `cancelled` | 何も表示しない（追加方式の画面に留まる） |
| 解析の警告 | 確認・編集画面の上部に注意として一覧表示。読み取った行は折りたたみで表示し、画面を閉じると破棄する |
| 算術の不一致 | `buildPayslip` のエラー文言を表示し、「調整項目を追加」「合計を見直す」の2つの導線を出す。差額を自動では入れない |
| 本人確認が未チェック | 保存ボタンを無効にし、理由を表示する |
| 同じ月が登録済み | 置換してよいか確認する。確認後は既存の id と createdAt を維持して保存する |
| 保存中 | ボタンを無効にし「保存中…」と表示する。失敗したら文言と再試行を出し、入力は保持する |
| 復元 | ファイル取得（2MBの確認は services が行う）→ JSON解析 → `parseBackup` → 「現在N件を削除し、M件に置き換え」の確認 → 置換 → 再読込した件数を表示 |
| 全削除 | 確認の欄に「削除」と入力してから実行する |

## 端末の余白（safe area）

`App.tsx` で `SafeAreaProvider` を置き、`src/ui/insets.ts` 経由で `useSafeAreaInsets` の実測値を使う。

## 非同期と画面の離脱

- 保存・削除・置換の実行中（`busy`）は、次の操作を止める。完了結果を別のモードや画面に表示しないためである。
  - タブ切替
  - 戻る操作（画面上とAndroidの両方）
  - デモの開始・終了
- `useAppData` は、モードを切り替えるたびに generation を進める。
  - 各操作は、開始時の repository を捕捉する。完了後の再読込も同じ repository で行う。
  - 途中で generation が変わっていたら、結果を反映せずに「切り替わった」エラーにする。
- 確認・編集画面で未保存の変更がある場合、離れる前に破棄を確認する。
  - 画面上の「閉じる」、Android の戻る、「やめる」では破棄の確認を出す。
  - デモ帯の「終了」では、「破棄してデモを終了」を確認する。
  - タブは確認・編集画面の表示中は出さない。
