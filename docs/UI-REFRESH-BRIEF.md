## 体験の骨格

1. ホームは「支払月と手取り → 前月との差 → 支給/控除の内訳 → 推移 → 最近の明細」の順序を明確にする。重要な内容を最初の画面に集め、余白と密度を両立する。
2. 青系の主色と濃いインク色、明るい中立色の背景で階層をつくる。白い面の角丸をそろえ、影と罫線を弱く使う。増減/警告/削除の意味色は混同させない。
3. 4タブの構成を維持し、ラベルと小さいアイコンを備える。丸いナビゲーションを浮かせる場合は、本文下の余白とsafe areaを確保する。
4. 日本語はシステムフォントを使い、数値を大きく、補助語を小さく配置する。重要金額を省略記号にしない。0・未入力・未登録・負数を区別する。
5. ホームだけでなく、履歴・ガイド・設定・追加方式・確認編集・詳細・初回案内・ダイアログを同じデザイン体系で更新する。
6. 追加方法は分かりやすい操作カード、フォームは見出しごとにまとまった面と明確な入力欄にする。保存確認や取り消しの導線を維持する。

## 動き

- ボタンの短い押下反応、タブの選択表示、画面/カードの短いフェードと移動を候補とする。約120〜240msを基本に、繰り返しの装飾アニメーションは避ける。
- 金額を途中の数値へカウントさせない。保存・確認をアニメーションの完了待ちにしない。
- React Native標準Animatedでopacity/transformを優先。スクロール位置やグラフの0基準を動きで壊さない。
- OS/Webの「動きを減らす」に追従し、状態が不明な間は静的に表示。切替・アンマウント時に動作とlistenerを停止する。

## 維持する構成と契約

- Expo / React Native、App.tsx → src/ui/AppRoot.tsx、既存screens、4タブと画面stack、src/domain・src/services・native moduleの境界を維持する。
- 新しいデザイン部品は既存src/ui内へ追加してよい。フレームワーク/Router/保存方式の移行はしない。
- 財務計算、法定額判定、データschema、OCR処理、バックアップ形式を変更しない。新しいスコア・予測・未実装操作を表示しない。
- 確認チェック、算術エラー、重複月の確認、未保存破棄、処理中の二重操作防止、デモ分離、Web非永続の説明を維持する。
- 既存UI-DESIGNの配色/余白/アイコン方針は今回の設計で更新できる。データ保全と操作上の保証は引き継ぐ。
- 依存は最小限。線アイコン/背景表現に必要なものは設計案で明示し、基盤担当がSDK互換版を一括導入する。参照画像やフォントのCDN読込を製品へ追加しない。

## 受入条件

- 全10観点（レイアウト/余白/カード/優先順位/文字/色/ボタン/ナビ/グラフと数値/密度）について設計案と実装の対応を示す。
- 320/390/430pxのモバイルと1280pxのWebで横はみ出し・欠け・重なりがなく、全操作へ到達できる。PCでは適切な最大幅へ収める。
- 押下領域44px以上、読み上げラベルと現在タブの状態、フォーカス、十分なコントラスト、動きを減らす設定を確認する。
- 正負混在/0/欠月/大きな金額の表示、手入力→保存、編集削除、デモ、JSON往復、置換取消/承諾を維持する。
- 既存73テスト・型/lint・関連E2E・Web/native production exportを通す。native依存変更があればAndroid/iOS compileも確認する。
- 設計と実装の節目でレビューし、架空データのbefore/afterと検証結果を保存して公開GitHubへpushする。
