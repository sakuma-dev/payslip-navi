## 0. コンセプト

**「青い給料日ステージ」と「白い読み取り面」。**

- 画面上部の青い面（ステージ）には、その月で一番大事な事実だけを置く: 支払月、手取り、前月比。
- ステージの下端に白いシート（読み取り面）が重なり、内訳・推移・比較を、小さく整列した数値カードで読ませる。
- 操作は丸い形（ピル型ボタン・円形アイコンボタン）、ナビは画面下に浮かぶ濃い色のピル型。
- 参照から採るのは「構成の考え方」だけ。DailyMeのスコアリング、目標達成率、円形ゲージ、挨拶文、グラスモーフィズムの丸は採らない。給与を評価する見た目にしない。

| 参照 | 採る考え方 | 採らないもの |
| --- | --- | --- |
| DailyMe | 主役の数値を置く青い上部面、下から立ち上がる白い面、暗いピル形の浮遊ナビ、丸い操作、追加方式を縦に並べた選択画面 | スコアのリング、週の丸いドット列、「目標まで」のグラフ、手書き風セリフ体 |
| Upstream | 小さな色の点＋ラベル＋大きな数値のコンパクトな行、矢印付きの増減チップ、区分ごとに整列した数値 | 円グラフ（給与の比率には割合帯のほうが読みやすい）、%表示 |
| Document Scanner | 大きな見出し＋アイコン付きの大きな操作カード、円形のアイコンボタン | 扇形のカード配置、全面グラデーション背景 |

色の規則:

- **増減の色は方向だけを示し、良し悪しを示さない。** 手取り・総支給・支給項目は `up`/`down`。控除合計・控除項目・調整は `neutralDelta` を使う（控除の増加を緑で見せない、減少を不安な色で見せない）。
- 増減は必ず **矢印アイコン＋符号付き金額＋「増/減/変化なし」の文字** の3点で伝える。色だけに頼らない。
- `down`（焦げ橙）と `danger`（深紅）は色相で分け、さらに形で分ける: 増減は常にチップ＋矢印、危険は警告アイコン＋淡紅面のボタン/バナー。
- 金額そのもの（手取り-100円など）は赤くしない。負の金額は `-` 記号と読み上げ「マイナス」で示し、文字色は `ink`。
- ダークモードは今回の対象外。明るいテーマに固定する。

### 2.2 ステージ（青い面）

- 縦グラデーション: 上 `primaryDeep #15398F` → 下 `primary #2458D0`。
- 右上に `#3E74F0` 不透明度0.28の大きな楕円を1つ重ね、光の当たった面の奥行きを出す（文字の置かれる左側には掛けない）。
- `react-native-svg` の `LinearGradient`/`RadialGradient` を `StyleSheet.absoluteFill` の `Svg` で描く。互換版を採用する。主文字は白、補助文字は不透明のonPrimaryMutedを使い、背景装飾込みで4.5:1以上を確保する。
- ステージ上の補足文字は `onPrimaryMuted`、主文字は `onPrimary`。

### 2.5 影

- カード: `boxShadow: '0 4px 16px rgba(22,33,58,0.06)'`＋1px `line` の罫線（RN 0.86の `boxShadow` はnative/Web共通。Android低性能端末でも罫線で輪郭が残る）。

### 4.5 設定タブ

2. **保存の状態**（新規の小さい要約カード、事実のみ）: `StatTile`「保存中の明細 N件」＋`shield` アイコン付き1行「この端末の中だけに保存」。Webプレビューでは代わりに「保存されません（Webプレビュー）」を `warning` 色で。

5. **データの削除:** 白カードに `danger` のボタン「すべてのデータを削除」。本文「登録済みのN件をすべて削除します。元に戻せません。」は文言を変えない（E2E依存）。

- 警告・問題のバナーは現状と同じ条件・文言で、見出しの直下。
- **操作カード（Scanner参照）:** 幅360以上は2列×2行のグリッド、360未満は1列。各カード: 角丸20、padding 16、最小高132（1列時は最小高76の横並び）。

  - タイトル（15/700、読み上げ名は現行どおり「撮影して読み取る」「写真から読み取る」「テキストを貼り付ける」「手入力する」）、説明（caption、2行まで表示し省略せず折返し）。

### 4.10 初回案内・読込中・失敗

- **初回案内:** 画面上半分が全幅のステージ（上角なし、下角丸28）。中身は原作のロゴ（白地の角丸16に、高さの違う3本の棒のSVG）、`largeTitle`「給与明細ナビ」白、現行の紹介文 `onPrimaryMuted`。下にシートを重ね、3つの約束を `shield`/`upload`/`check` のアイコン行で表示。Webプレビュー時は注意バナー。最下部に主ボタン「自分の明細を追加する」、secondary「サンプル（架空データ）で体験する」。

## 6. 動き（`src/ui/motion.ts`）

### 6.1 原則

- 標準の `Animated` と `AccessibilityInfo` だけを使う。追加の動きライブラリは入れない。
- 動かすのは `opacity` と `transform`（translate / scale / rotate）だけ。幅・高さ・top・値は動かさない。
- **金額は最初から最終値で表示する。** 数値のカウントアップ、棒が0から伸びる演出、基準線やグラフ位置の移動、スクロール連動の視差はしない。
- 繰り返す装飾（点滅、脈動、シマー、ループ）はしない。一度きりの短い動きだけ。
- 保存・削除・置換・画面遷移を動きの完了待ちにしない。onPressの処理は即時に実行し、動きは見た目だけ。
- `useNativeDriver: Platform.OS !== 'web'`（Webで警告を出さない）。

### 6.2 動きを減らす設定

- `MotionProvider` 1か所で `AccessibilityInfo.isReduceMotionEnabled()` と `reduceMotionChanged` を購読し、子はContextから状態を読む。初期はunknownとして静的。Webは実装済みAPIを確認し、必要ならmatchMediaで `prefers-reduced-motion` を読む。
- 入場系はマウント時の確定状態でだけ判断し、unknownで既に表示した内容を後からopacity 0へ戻さない。押下/開閉/選択は設定変更に追従する。
- アンマウント後の結果反映をフラグで防ぎ、クリーンアップで `subscription.remove()`。
- reduced のとき: すべての入場・開閉・押下の動きを行わず、最終状態を直接表示する（押下は背景色の変化だけ）。

### 6.4 実装の形とクリーンアップ

`motion.ts` に次を置く:

- `duration`（`press: 90`, `release: 140`, `fast: 160`, `base: 200`, `slow: 220`, `emphasis: 240`）と `stagger: 40`、`maxStaggerItems: 4`。
- `useReducedMotion()`（§6.2）。
- `useEnterAnimation({ from, delay, reduced })` → `{ opacity, transform }` スタイル。`useRef(new Animated.Value(…))` で1回作り、`useEffect` 内で `Animated.timing(...).start()`、クリーンアップで `anim.stop()`。reduced なら値を最終値に `setValue` して開始しない。
- `usePressScale(reduced)` → `onPressIn`/`onPressOut` と style。実行中のアニメは新しい押下の前に `stop()`。
- `useToggleAnimation(open, reduced)` → 0↔1 の値（回転と中身のフェードに使う）。
- `AnimatedPressable = Animated.createAnimatedComponent(Pressable)` をここで1回だけ作る。

規則:

- `setTimeout` / `setInterval` / `requestAnimationFrame` を直接使わない（遅延は `Animated.delay` / `Animated.stagger`）。
- すべての `start()` はクリーンアップで `stop()` される。`start` のコールバックでstateを更新しない。
- アンマウントされた要素の出口アニメーションは作らない（Modalやスタックは即時に外す）。
- テスト環境（vitest）ではアニメーションに依存しない。純粋関数のみテストする。

## 7. 金額・グラフ表示の制約（チェックリスト）

1. 金額の表記は `formatYen` の結果だけ。万円への丸め、「…」、`numberOfLines` による切り捨てをしない。長い金額は段階縮小→折返し。
2. 負の金額は `-` 付きの `formatYen` 表記、読み上げは「マイナス」。文字色は赤にしない。
3. 0円は「0円」。変化なしは「±0円 変化なし」の中立チップ。
4. 「未入力」（編集中の空欄）、「内訳未登録」、「データなし」（比較月なし）、「未登録」（推移の欠月）、「0円」を区別し、文言を現行から変えない。
5. 差額は常に「当月 − 比較月」。比較先の月を必ず併記する（「前月（2026年8月）比」）。
6. 比較は現行の `comparePayslips` の結果だけを使う。直前に登録された別の月とは比べない。
7. 推移は `buildTrend` と `layoutBars` のまま。0円の基準線を常に描き、正は上・負は下。棒の高さ・位置を動かさない。
8. 割合帯は §4.1 の条件を満たすときだけ。%、スコア、目標、平均、予測、ランクは表示しない。
9. 事実（計算した差）と可能性（考えられる理由）を見出し・カードの色（白 / soft）・バッジ（「可能性」）で分ける。可能性には出典と確認日を付ける。
10. 「算術チェック」は税額の検算ではないという文言を、詳細・編集・設定で維持する。
11. 金額はすべて tabular-nums、一覧では右寄せ。
12. 増減は色・矢印・符号・文字の4つで伝える。控除の増減は中立色。

## 14. レビュー06を受けた確定条件

この節と上の修正箇所が実装時の正本。旧い寸法の目安と食い違う場合はこの条件を優先する。

- H1: タイル内幅は画面ガターだけでなくシートpadding、gap、タイルpaddingを差し引く。推定幅を超える金額は1列へ。詳細タイルも基本moneyL(20px)に統一。320/390幅と300,000円/1,234,567円/-1,000,000,000円、fontScale1/1.3/1.6を確認する。
