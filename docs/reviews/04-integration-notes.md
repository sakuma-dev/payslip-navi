# 統合点検メモ

対象: 157f032 のGUIと保存サービス。2026-09-28。ソースと架空データ画面の点検。初回指摘と対応結果を記載し、3件とも修正済み。グラフの追加境界修正も05で再点検済み。

## 初回の指摘

1. **復元失敗時の状態を断定しない（Medium）**
   `SettingsScreen.doRestore` はすべての例外で「置き換えは取り消され、元のデータのまま」と表示する。しかしSQLiteの変更はコミット後の再読込が失敗した場合にも例外になり、既に置換済みの可能性がある。検証で拒否した場合と、書込/再読込で結果を確認できない場合を分け、後者は一覧の再読込を促す。復元後の原状維持を未確認のまま断定しない。

2. **共有シートの終了を保存完了と表示しない（Medium）**
   `shareBackup` はvoidで、共有キャンセルや他アプリでの保存成否を通知しない。`doExport` の「書き出しました」「保存先は選んだ場所」はこの結果から保証できない。出力/共有操作を行ったことと、ユーザーが保存先で確認することを伝える。

3. **負の手取りをグラフで切り捨てない（Medium）**
   `TrendChart` はheight計算で `Math.max(0, value)` を使うため、負の金額はすべて同じ最小高になる。負値も登録可能な仕様なので、0基準線の上下で大きさを表すか、負値がある場合は数値表示を主体にして棒の意味を明示する。未登録、0円、負数を区別する。

## GUI対応結果（2026-09-28 / Claude Opus 5.5 medium）

1. **復元:** `doRestore` の例外時に、元のデータのままだと断定する文言をやめた。表示は警告「復元の結果を確認できませんでした」と、「置き換えが完了している場合と、元のデータのままの場合があります」という案内。「一覧を読み直す」ボタンは `useAppData.refresh` で、同じ保存先から読み直して件数を表示する。
   - 事前の段階（ファイル選択、JSON解析、`parseBackup` の拒否）では書込前なので、従来どおり「現在のデータは変更していません」と表示し、書込後の失敗とは分けている。
   - 置換の確認ダイアログの説明も「取り消す仕組みです」に改め、結果を保証する表現をやめた。
   - 全削除の失敗も同じ扱いにした（「削除の結果を確認できませんでした」と読み直しの導線）。
   - 確認・編集画面と詳細画面のエラー見出しは「〜でエラーが発生しました」にした。確認・編集画面は、同じIDで再試行しても重複しない。
2. **書き出し:** 見出しは「書き出しの操作を終えました」。本文では、共有・保存の画面に渡したこと、取り消した場合や保存先によっては保存されていないこと、保存先でファイルを確認してほしいこと、金額がそのまま入っていることを伝える。保存を完了したとは表示しない。
3. **推移グラフ:**
   - 棒の配置を `src/ui/chartScale.ts` の `layoutBars`（純粋関数）で計算する。0円の基準線を境に、正の値は上へ、負の値は下へ、絶対値に比例した高さで伸ばす。負の値がない年は、基準線が下端になる。
   - 色以外の区別: 正の値は塗りの棒、負の値は破線の枠だけの棒で基準線の下、0円は基準線上の輪の印、未登録は「–」。凡例にも形で書いてある。
   - 読み上げの要約と数値一覧は残している。未登録は「未登録」、負の値は「マイナス…円」と読む。
   - テスト: `src/ui/chartScale.test.ts`（5件。正の値のみ、正負の混在、負の値どうしで大きさが残ること、0円と未登録の区別、すべて空）。
   - 操作確認の条件: 架空データで、ある月の差引支給額を負の値（例: 総支給0、控除100、差引-100）にして保存し、ホームの推移を表示する。基準線より下に破線の枠が出ることと、数値一覧に「-100円」が出ることを確認する。

### 追記: 推移グラフの符号境界の修正（2026-09-28 / Claude Opus 5.5 medium）

- **再現した不具合:** `layoutBars([250000, -100], 132)` では、基準線が132（下端）になり、負の棒が top=129 と基準線の上側に出ていた。`[1, -1000000000]` では逆に、正の棒が基準線の下側に出ていた。原因は、最小高（3px）へ引き上げた棒を領域内に押し戻すときに、符号の側を越えていたこと。
- **修正（`src/ui/chartScale.ts`）:**
  - 基準線は、共通の比例スケールで置いたうえで、値がある側に最小高ぶんの余白を確保する。正の値があれば3px以上、負の値があれば `area-3` 以下にする。
  - 正の棒は `height ≤ baseline` で `top = baseline − height`、負の棒は `top = baseline` で `height ≤ area − baseline` とし、自分の側を越えない。
  - 比例スケールが崩れるのは、最小高と余白の境界だけ。微小な値は数値一覧と読み上げで正確な値を補う。
  - `TrendChart.tsx` は、0円の印の位置を領域内に収める調整だけ。
- **テスト（`src/ui/chartScale.test.ts`）:**
  - 上の2例に加え、正負の混在、±1、±10億、狭い領域（area=10）で不変条件を確認する。不変条件は「正の棒は `top+height ≤ baseline`、負の棒は `top ≥ baseline`、`0 ≤ top ≤ top+height ≤ area`」。
  - 修正前に2件が失敗することを確認し、修正後に全件passした。
