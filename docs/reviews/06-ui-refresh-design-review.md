## High（契約確定前に修正）

### H1. 320px で数値タイルの金額が収まらない（§3 StatTile / §4.8 / §8）
- 再現: 幅320、ガター16 → シート幅288、シート padding 20 → 内幅248、2列 gap 12 → タイル118、タイル padding 12 → **文字幅約94px**。`moneyL` 20px/700 の tabular 数字を約0.57em とすると「300,000円」≈94px（境界）、「1,234,567円」≈111px、「1,000,000,000円」≈158px。§8 の「各約136」はシート padding を引き忘れている。
- 詳細ステージの半透明タイルは `moneyXL` 26px のため「300,000円」≈122px で、320では通常の金額でも収まらない。390でも境界になる。
- 省略記号禁止のため、実装すると数字の途中で折り返す（「1,234,56 / 7円」）。
- 修正条件: 純粋関数（例 `tileColumns(width, fontScale, texts)`）で、formatYen の最長文字数×推定字幅がタイル内幅を超える時は1列にする。`fontScale>1.3` だけの規則にしない。詳細ステージの2タイルも同じ規則にするか、`moneyL` へ下げる。`visual.test.ts` で 320/390 × {300,000 / 1,234,567 / -1,000,000,000} を境界テストする。

### H2. 割合帯の色が誤った対応を示す（§4.1 SplitBar / §2.1）
- 帯の青は「手取り」（`primary #2458D0`）、左タイル「総支給」の点は `catEarning`＝同じ `#2458D0`。帯の下に凡例がないため、「青＝総支給」と読まれ、構成比を誤解させる。シートに手取りのタイルはない。
- 修正条件: 帯の直下に文字の凡例「● 手取り 250,000円　● 控除合計 50,000円」を置く（%は出さない）か、総支給タイルの点を帯と別の色/形にして「総支給＝帯全体」を文字で示す。色だけで対応させない。読み上げラベル（「総支給…のうち手取り…控除合計…」）は現案どおりでよい。

### H3. 入力欄などの境界コントラストが不足（§2.1 / §3 Field・Checkbox・Chip・Segmented / §8）
- `lineStrong #C9D2E0` は白上で **1.52:1**（計算値）。§8 の「入力枠3:1以上（確認済み）」と矛盾する。`Field` の枠と未選択 `Chip` の枠がこの色。`Checkbox` の未チェック枠は色が未指定。
- `Segmented` の選択カプセルは白で、地は `surfaceSunken #F3F6FB`。差は **1.09:1** で、選択状態がほぼ見えない。
- 修正条件: 入力枠と未チェック枠は白上で3:1以上にする（例: `#7A8AA6` なら3.49:1）。フォーカス枠（`primary` 2px）は現案でよい。Segmented の選択は、文字色/太さの変化に加えて3:1以上の枠か影を持たせる。§8 の「確認済み」は実測値の表に置き換える。

### H4. ボトムシート化した Dialog で入力がキーボードに隠れる（§3 Dialog / §4.5）
- 再現: iOS、幅<600、設定→「すべてのデータを削除」。シート内の「確認のため削除と入力」をフォーカスする。シートは下端固定で、`Modal` の中には KeyboardAvoidingView がない（AppRoot の KAV は Modal の外）。そのため入力欄と「すべて削除する」がキーボードの下に隠れる。
- 修正条件: 入力を含む Dialog は、Modal 内で `KeyboardAvoidingView`（iOS padding）と ScrollView で包む。または入力を含む Dialog は中央表示に限る。Android（adjustResize）と Web 320px で、入力・主ボタン・取消が見えることを受入条件に加える。

## Medium（実装の受入条件）

- **M1 普通文字・図形のコントラスト（計算値）**
  - `inkSubtle #6B768C` は白上4.57:1でよい。ただし canvas 上は4.07:1、`surfaceSunken` 上は4.22:1で不足する。受入: 白地だけで使う。canvas/タイル上の文字は `inkMuted`（canvas上5.46:1）にする。
  - ステージ右上の楕円（`#3E74F0` α0.28）が掛かる部分の合成色は約 `#2B60D9`。この上の `onPrimaryMuted` は約4.45:1で不足する。受入: 320px で折り返した caption・前年同月比・デモタグが楕円に掛からないことを実描画で確認する。確認できない場合は α を下げる。
  - 0円の基準線 `inkFaint #A3ADC0` は白上2.26:1。正負の意味を持つ図形なので3:1以上（例 `inkMuted`）にする。0円の印の色も3:1以上で明記する。ガイドの `other` の点（同色）には区分名の文字も付ける。
- **M2 文字拡大と巨大金額**
  - `display` 32px × 1.3 の「-1,000,000,000円」は約310pxで、320のステージ内幅（約288）を超え、数字の途中で折り返す。受入: `displayStep` に幅と fontScale を入れ、もう1段（例 28）を追加する。折返しは「円」の前だけに限る。
  - DeltaChip（1.6倍時 約270px）が行幅を超える時は、ラベルの下へ回り込ませる（flexWrap）。
  - 浮遊ナビ「項目ガイド」は1.3倍でカプセル内幅（約64）を超える。ナビラベルは `maxFontSizeMultiplier` を明記する（例 1.2）か、高さを可変にする。
  - ステージ・シートは固定高にしない（§4.1 の y 座標は目安と明記する）。
- **M3 reduced motion の初期値と再生時期**
  - 初期値 true（静的）のまま M5 をマウント時1回とする。後から false が届いた時に effect が再実行されると、表示済みのブロックが opacity 0 に戻ってから出直す（点滅）。
  - 受入: 入場系（M3/M4/M5/M10/M11）はマウント時点の確定値だけで判断し、未確定なら再生しない（後から再生しない）。`reduceMotionChanged` の反映は押下・開閉・切替だけにする。
  - 購読は各部品ごとではなく、モジュール1か所（Context 等）で1回にする。アンマウント後の set を防ぐ現案は維持する。
- **M4 Web の44px**: Chip 36、Segmented 40、デモ「終了」32、年送り36、戻るピル40 は hitSlop に依存している。RN Web では hitSlop で押下領域が広がる前提にできない。受入: Web では minWidth/minHeight 44 の透明領域（padding）で確保し、Playwright の boundingBox で 320/390 のとき44以上であることを確認する。
- **M5 押せない物・誤解を招く表示**
  - §4.2 の「追加できる方法」4アイコンは、操作カードと同じ見た目なので押せそうに見える。Web では撮影・写真は使えない。受入: 円形アイコン地やカード形をやめて本文の箇条書きにし、使えない環境では「開発ビルドで利用可」と併記するか省く。
  - §4.5「保存の状態」: デモ中は「デモ（架空データ・保存されません）」にする。`shield` は保護・暗号化を連想させる。アプリ独自の暗号化はないと明記している（Settings の現行文）ので、端末アイコン等の中立な図にする。§4.10 の約束行も同様にする。
- **M6 割合帯の境界**（`splitBarModel` のテストに含める）
  - 全て0円の明細では「調整やマイナスの金額があるため」が事実と異なる。受入: 非表示の理由文は条件ごとに出し分けるか、中立の文言にする（例「この明細では構成の帯を表示しません」）。
  - netPay=0（総支給＝控除）の時は控除だけ、控除=0の時は手取りだけにし、0幅の区画と2pxの隙間を出さない。
  - 微小な区画に最小幅を足して比率を偽らない。
  - 調整項目があり合計が0の場合は、等式が成り立つので表示してよい。この扱いを明記する。
- **M7 推移の強調ラベル**: 320で1列は約20px。「250,000円」（micro 700、約55px）は隣の列に重なる。最大の棒の上は `layoutBars` の範囲外に出る。受入: 値はプロット領域の外（カード上段の caption「9月 250,000円」等）に置き、`layoutBars` と棒の位置は変えない。M7 は新しい年の内容だけをフェードさせ、旧年の棒・数値を重ねて残さない（値が一瞬別の数字に見えるのを防ぐ）。

## 最終判定（反映確認後・2026-09-28）

**承認。** 未解決の High はない。確認したのは §2.1、§4.1、§6.2、§8、§14 の差分。

- H1: `tileColumns(containerWidth, fontScale, formattedValues)` で、シート padding・gap・タイル padding を引いた内幅から列数を決める（§8、§14）。詳細タイルは moneyL に統一した。`displayStep` を幅と fontScale 入りの5段にし、数字の途中で改行しないことを明記した。解消。
- H2: 割合帯に文字付きの凡例を付けた（手取り／控除合計）。総支給タイルの点を凡例の代わりに使わない。0の区画・隙間・最小幅は足さない。合計0の調整は表示してよい。解消。
- H3: `lineStrong #7B8598` は白上 3.716 で、再計算でも一致した（sunken 3.431、primarySoft 3.165 は親の実測）。入力・未チェック枠・Chip に使う。Segmented は primary の輪郭と太字で選択を示す。0基準線・0の印・未登録記号は3:1以上。解消。
- H4: Dialog 内に KeyboardAvoidingView と ScrollView を置く。入力付きは中央表示も可。Android・短い Web・320px で確認する。解消。
- M/L: 次をすべて §14 の受入条件に入れたことを確認した。inkSubtle `#606B82`（最悪 4.559）、onPrimaryMuted `#E3EBFF`（楕円合成上 4.657）、文字用 opacity の禁止、MotionProvider での1回購読、unknown 後に再入場しない、実寸44（boundingBox で確認）、盾アイコン廃止、推移の値をプロット外へ、年切替で旧値を重ねない、暦上の前月比較、StatusBar／帯の規則、M11 省略。
