## 2. レビュー10 の指摘ごとの根拠

### M1 設定の件数（G3-C1）: 解消

- `SettingsScreen.tsx:156`: 実データでもデモでも見出しは「表示中の（デモの）明細」。「保存中」という断定は無くなった。
- 保存先は、件数と切り離して仕組みとして説明している。
  - native:「明細の保存先はこの端末の中だけです…」
  - Web:「Webプレビューでは保存されません…」
- 削除カードも「表示中の明細はN件です。保存先の明細をすべて削除します。元に戻せません。」となり、件数と削除の範囲が分かれた。
- notice・`reload`・結果不明の分岐・確認 Dialog・無効化の条件は、差分に含まれていない。
- 撮影（320/390 の設定）はデモ時で、「表示中のデモの明細 6件」を確認した。実データ時の見出しは、コードと E2E の文言で確認した。
- 残る件は無い。

### M2 金額欄の「円」と支払月: 解消

- 修正: `styles.input` に `minWidth: 0`、単位に `flexShrink: 0` を足した。
  - 入力の DOM 構造（枠＞input＋単位）と、value・ref・keyboardType は同じ。
- 撮影で確認した。
  - 390/430 の editor-field と editor-top、1280 の editor-top: 入力値「1234567」・placeholder・「円」がすべて枠の内側にある。
  - 320 の editor-field: 支払月「2026-09」が欠けずに表示されている。
- 追加された E2E（320/390/430 で実打鍵とフォーカスを保持）は、input と単位の右端が枠の右端の 1/64px 以内にあることを断定している。
- 支払月も、320 で「2026-12」の文字幅が入力の内幅以下で、scrollWidth も clientWidth 以下であることを断定している。
- 許容差は、G-C1 と同じ丸めの幅だけ。

### M3 320 のスタック見出し: 解消

### Low の対応

- **L-a 貼付のパネル: 解消。**
  - 320 の撮影で「テキストを貼り付ける」→ 入力パネル →「手入力する」の順を確認した。390 の2×2 では、グリッドの下に全幅で開く。
  - 実装では、パネルの key は固定。列数が変わる時は、状態を持たない「手入力する」カードの key だけを変える。React の key の照合でパネルは移動もせず、作り直しもされない。この読みは、GUI 担当の「幅を変えても同じ textarea・値・フォーカス」という報告と一致する。
  - 貼付の本文は、親の state のまま。
- **L-b Detail の0項目: 解消。**「登録された項目はありません」になった。
- **L-c 算術チェック: 解消。**
  - 390 の editor-end で「控除合計：」「差引支給額（手取り）：」の前置きを確認した。
  - 判定と文言は domain のまま。`issueSubject` は path を表示名に変えるだけ。
- **L-d 強制色の G3 撮影と `data-forced-fill` の E2E: 未実施（継続）。**
  - Onboarding のロゴは装飾として設計を改めた（強制色では省略を許容）。aria-hidden なので受け入れる。
- **破棄 Dialog の題:**「入力を中止しますか」（新規）と「編集を中止しますか」（編集）になった。320 の撮影で確認した。
  - 新規の時も、続ける方のボタンは「編集を続ける」のまま。語は少し揃っていないが、操作の意味は取り違えないので指摘にはしない。
